# 연구 실행 로드맵 — DGVC 상세 마일스톤

기준일: **2026-11-03 (KST)** · 계획 버전: **1.0** · 적용: **DGVC v2.1**

기존 M0~M7을 **23개 세부 게이트**로 나눈 실행 계획이다. 연구질문·가설·변수 정의는 [연구 프로토콜](PROTOCOL.md)을 따른다. 일정은 목표이며 날짜 도달이나 코드 존재만으로 완료 처리하지 않는다.

**현재 상태: M0~M5 완료.** 인증된 실제 자료의 사전 모형 추정·가설 평가와 강건성 점검을 마쳤다. 다음은 G-M6-01 보고서 초고다.

## 1. 현재 기준선과 남은 차이

기준 코드: `071d9a9`. 다음은 코드·문서에서 관찰한 상태이며 게이트 완료 판정이 아니다.

| 영역 | 관찰한 구현 | 추가로 필요한 증거 / 작업 |
|---|---|---|
| 설계 | H1/H2, 변수·시점·잠정 지역처리 규칙 문서화 | 문헌 근거 점검, 미결정 항목과 확정 시점 명시 |
| 입력·결합 | 표준 CSV, 코드 매칭, 계수 합산 후 비율 계산 | 실제 원자료 변환, 지역·연령 전체 범위 검증 |
| 수치 검증 | 범위·중복·필수 값 검사 일부 구현 | 잘못된 `reported_turnout` 문자열과 진짜 결측 구별 |
| 회귀 | M1~M4, HC3, WLS, 공통표본 재추정 구현 | 수치 검증, 실제 표본 명단·모형 정보·결과 검수 |
| 탐색분석 | 기술통계·상관·산점도 코드 존재 | 회귀보다 먼저 독립 실행할 경로와 그림 검수 |
| 강건성 | WLS·공통표본 코드 존재 | 특수지역 감도분석, VIF·영향점·탐색적 상호작용 |
| 자료·출처 | 입력 양식과 공식 자료 경로 문서화 | 공식 원본 4종 및 투표율 비교자료, 이용조건·해시 |

앞선 로컬 준비 점검에서는 Python 3.12.12의 인공 데이터 테스트 **6개**, Ruff와 컴파일 검사가 통과했다. 이는 이전 작업의 코드 기준선이며, 본 계획 작성 중 새로 수행한 검사나 실제 자료의 타당성 증거로 재사용하지 않는다. 구현 시작 시 관련 검사를 다시 실행한다.

임시 인공 입력에서 확인한 공백은 다음과 같다. 정식 회귀 테스트는 아직 추가하지 않았다.

- 선거·인구에서 같은 분석 지역이 함께 빠지면 현재 결합 검사가 누락을 발견하지 못함 → G-M2-06.
- 일부 연령 행을 제거해도 현재 인구 검사가 통과함 → G-M2-03, G-M2-06.
- `reported_turnout`의 잘못된 문자열이 결측처럼 통과함 → G-M0-02.
- 품질보고서의 공식 집계 검증 상태와 분석 실행이 연결되지 않음 → G-M2-06, G-M3-01.

## 2. 게이트 운영 계약

### 상태와 범위

- 상태: `DRAFT → LOCKED → IMPLEMENTING → VERIFYING → DONE`. 일부 조건이 남으면 `PARTIAL`, 필수 선행조건이 막히면 `BLOCKED`로 기록한다.
- 한 번에 실행하는 구현 게이트는 하나다. 아래 목록은 대기열이며, 시작할 게이트의 조건과 실제 파일 경로를 먼저 잠근다. 사용자가 일련의 작업을 승인한 경우 그 범위 안에서 순차적으로 잠그고 진행할 수 있다.
- 마일스톤 완료는 소속 게이트가 모두 `DONE`일 때만 인정한다. 선행조건을 기다린다는 이유로 대기 중인 게이트를 미리 `BLOCKED`로 바꾸지 않는다.
- 기본 모드는 **Standard**다. 현재 계획 문서 정비처럼 국소적인 문서 작업은 **Lightweight**로 수행한다. 개인정보·인증·권한·파괴적 데이터 변경·운영환경 변경을 포함하게 되면 **Critical**로 재분류해 경계와 검증을 추가한다.
- 아래 허용 경로와 새 산출물 이름은 **실행 시 사용할 계획**이다. 파일의 존재나 생성 완료를 뜻하지 않는다. 범위 변경은 해당 게이트를 다시 잠근 후 진행한다.

### Standard 공통 필드

각 게이트는 다음 공통 계약과 해당 상세 항목을 함께 적용한다. 실행 직전에 미정 사항을 해소해 한 개의 구체적인 계약으로 잠근다.

| 필수 필드 | 적용 내용 |
|---|---|
| Gate | 아래 `G-Mx-yy` ID, 모드, 상태, 시작 시 코드 기준점 |
| Goal | 해당 상세 항목의 단일 목표 |
| Acceptance criteria | 해당 AC 전부. 마일스톤 출구 조건은 소속 게이트를 종합해 별도로 판정 |
| Non-goals | 결과에 맞춘 가설·표본 변경, 개인 행동·인과효과 추론, 무관한 리팩터링·UI·자동 수집 플랫폼 구축은 제외 |
| Intended sources | 현재 사용자 요구, `PROTOCOL.md`, `CODEBOOK.md`, `DECISIONS.md`, 해당 원자료의 공식 메타데이터 |
| Observed sources | 시작 시 `git status`·관련 diff, 실제 코드·테스트, 사용 원본·입력·산출물 해시와 실행 결과 |
| Allowed surfaces | 상세 항목의 경로와 `docs/RESEARCH_LOG.md`; 연구설계 결정을 바꾸면 관련 문서를 명시적으로 추가해 다시 잠금 |
| Forbidden surfaces | 무관한 파일, 기존 사용자 변경과 DOCX, `.git/`, 자격증명; 내려받은 원본 바이트의 덮어쓰기·수정·삭제 |
| Validation | 상세 항목의 검사 + 변경 성격에 맞는 6절의 공통 검사. 각 AC에 검사·결과·증거를 연결 |
| Recovery | 게이트가 만든 변경만 diff로 식별해 수정·복구. 원본은 유지하고 실패 파생물은 별도 실행 경로로 분리. 전체 작업트리 초기화 금지 |
| Closeout location | 기존 `docs/RESEARCH_LOG.md`에 날짜·Gate·상태·변경 경로·AC별 실제 검사·증거 위치·미해결 사항 기록 |
| Next handoff | 상세 항목의 다음 게이트, 전달 파일·해시·결정·남은 제약. 자동 착수나 승인으로 간주하지 않음 |

검사 결과는 `PASS`, `FAIL`, `SKIPPED`, `BLOCKED`, `NOT_APPLICABLE`로 구분한다. 필수 검사를 실행하지 않았으면 `DONE`으로 닫지 않는다. 파일 존재·헤더 검사와 실제 내용 검증을 구별하고, 인공 데이터·공식 수치 대조·재현성 검증을 각각 기록한다.

## 6. 검증·증거·완료 기준

### 실제 존재하는 공통 명령

저장소 루트에서 `.venv` 활성화 후 사용한다. 아래는 **실행 계획**이며 기재 자체가 `PASS` 증거는 아니다.

```bash
source .venv/bin/activate
python -m pytest
python -m ruff check src tests
python -m compileall -q src
git diff --check
```

- 문서만 변경: `git diff --check`, 링크·ID·상호참조·범위·내용 일치 검사.
- 코드 변경: 관련 결함 재현 후 관련 테스트·전체 기존 테스트·Ruff·컴파일 검사. 기능 이름만 확인하는 테스트로 계산 타당성을 대신하지 않는다.
- 실자료 빌드: 입력·대응표 확보 후 `make build`. 성공만으로 공식 집계 검증을 완료 처리하지 않는다.
- 회귀: M2~M3 조건 통과 후 `make analyze`. 탐색·강건성의 추가 명령은 구현 시 확정하며 아직 있다고 가정하지 않는다.
- 시각 산출물: 실제 생성한 모든 그림/최종 제출물의 축·글꼴·표·페이지를 해당 형식에서 직접 확인한다.

### 기록할 최소 증거

기존 `docs/RESEARCH_LOG.md`에 Gate ID·상태·실행일, 코드 기준점/변경 경로, 입력·산출물 해시, AC별 명령/수동 확인·실제 결과·증거 위치, 제외/결측/차이 사유, 미완료·다음 인계를 남긴다. 큰 검사표·수치·그림은 `outputs/`에 두고 기록에서 연결한다. 별도 템플릿·캐시·아카이브 계층을 자동 생성하지 않는다.

실제 자료와 `outputs/`의 Git 비추적 정책을 유지한다. 로컬 증거 경로만으로 제3자 재현이 가능하다고 보지 않는다. 공유할 자료는 이용조건에 따라 공식 재취득 절차 또는 별도로 승인된 전달 방법을 M7에서 문서화한다. 원본 전체 내용을 문서에 복사하거나 자격증명을 기록하지 않는다.

### 최종 완료 판정

M7 종료에는 공식 자료 검증, 분석·보고 수치 재현, 제3자 재실행, 최종본 검수가 모두 필요하다. 가설 지지 여부는 완료 조건이 아니다. `BLOCKED`/`PARTIAL` 또는 필수 검사 미실행을 일정 때문에 `DONE`으로 바꾸지 않는다.
